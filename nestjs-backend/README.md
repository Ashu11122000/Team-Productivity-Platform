# Team Productivity Platform — NestJS Backend

Enterprise-grade **NestJS Backend API** for the **Team Productivity Platform**.

This backend is responsible for productivity management features including:

- Task Management
- Categories
- Tags
- Notifications
- Reminders
- Activity Logs
- Analytics
- Dashboard
- Calendar
- External Integrations

The project follows **Clean Architecture**, **SOLID Principles**, **Repository Pattern**, **Service Layer Pattern**, **Provider Pattern**, and **Mapper Pattern** to provide a scalable, maintainable, and production-ready backend.

Unlike traditional monolithic applications, authentication is handled by a dedicated **FastAPI** service. This NestJS backend validates JWT tokens generated by FastAPI and focuses entirely on productivity-related business logic.

---

# Overview

The Team Productivity Platform is built using a distributed backend architecture.

Authentication and productivity management are intentionally separated into independent services.

```
                     +----------------------+
                     |    Next.js Frontend  |
                     +----------+-----------+
                                |
                                |
                        JWT Authentication
                                |
                                ▼
                  +----------------------------+
                  |      FastAPI Backend       |
                  |----------------------------|
                  | Authentication             |
                  | User Management            |
                  | Notes                      |
                  | JWT Generation             |
                  +-------------+--------------+
```

# Authentication Architecture

Authentication is fully owned by the FastAPI backend.

NestJS **never** performs authentication operations.

NestJS does **not**:

- Register users
- Authenticate users
- Generate JWT tokens
- Store passwords
- Refresh tokens

NestJS only validates JWT tokens before allowing access to protected APIs.

Authentication flow:

```
User
 │
 ▼
FastAPI Login
 │
 ▼
JWT Token
 │
 ▼
Next.js Frontend
 │
 ▼
NestJS Request
 │
 ▼
JwtAuthGuard
 │
 ▼
JwtStrategy
 │
 ▼
Authorized Request
```

---

# JWT Contract

The NestJS backend validates JWT tokens generated by FastAPI.

Validation includes:

- JWT Signature Verification
- Token Expiration Validation
- JWT Issuer Validation
- JWT Audience Validation
- Payload Integrity Validation

Only validated requests are allowed to access protected APIs.

Every protected endpoint requires:

```
Authorization: Bearer <access_token>
```

# Clean Architecture

The backend follows **Clean Architecture** to ensure clear separation of concerns and maintainable business logic.

Each feature module follows the same implementation pattern.

```
                Controller
                     │
                     ▼
                 Service Layer
                     │
                     ▼
               Repository Layer
                     │
                     ▼
                  Mapper Layer
                     │
                     ▼
            Request / Response DTOs
                     │
                     ▼
              TypeORM Repository
                     │
                     ▼
                 PostgreSQL
```

---

## Layer Responsibilities

| Layer | Responsibility |
|--------|----------------|
| Controller | HTTP request handling |
| Service | Business logic |
| Repository | Database operations |
| Mapper | Entity ↔ DTO conversion |
| DTO | Request & Response contracts |
| Entity | Persistence model |
| Provider | External integrations |
| Integration | Third-party service communication |

Business logic never resides inside Controllers or Repositories.
